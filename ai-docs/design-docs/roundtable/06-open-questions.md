## 明确不做（不属于本包）

| 事项 | 理由 |
| --- | --- |
| 内置角色库 | 违反「Prompts are business assets」；用 `init` 生成示例替代 |
| 采集器（RSS / 网页 / 数据库） | 圆桌只接收 `context`，采集由使用者或其它包负责 |
| 模型供应商适配 | 统一走 `@cikit-js/ai`，不在本包重复实现 |
| 定时调度 | 由 CI（GitLab schedule / cron）负责，`schedule` 字段只是人读声明 |
| 席位 `extends` 继承 | 等真的出现重复写再抽，避免过早抽象 |
| 流式输出 | CLI / CI 场景下对日志和管道无价值 |
| Web / 可视化界面 | 先跑通 CLI 与 Markdown，界面另议 |
| 独立发版 | 跟随 monorepo 统一版本，见 [README.md](README.md) 决策 8 |

## 需要观察后决定

| 事项 | 观察什么 |
| --- | --- |
| 是否需要 `special.propose` / `special.converge` 显式声明 | 自定义阶段名时，按名字推断是否够用 |
| `threshold` 默认 0.5 是否合适 | 真实使用中是否频繁需要调高或调低 |
| `weight` 的实际使用频率 | 若几乎无人使用，考虑简化为一票一权 |
| `parallel` 阶段的实际收益 | 若模型在并行阶段产出质量明显下降，考虑移除 |
| `invalid-veto`（空理由否决）是否要更严格 | 若出现「否决但不给理由」的滥用，改为一律作废该席位本轮投票 |
