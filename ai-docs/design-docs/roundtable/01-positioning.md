# 定位与边界

## 它是什么

`@ci-kit/roundtable` 是**讨论平台**：让一组 AI 席位像人一样在同一张桌子上你一言我一语，讨论结束后给出可追溯的结论。

它只认识四个抽象，不含任何业务或角色语义：

| 抽象 | 含义 | 谁定义 |
| --- | --- | --- |
| **席位** | 一个与会者：什么身份、什么性格、怎么说话、有什么权 | 项目写 `seats/*.md` |
| **讨论** | 聊多久、花多少、怎么裁决 | 项目写 `table.md` |
| **桌面** | 大家共同看到的外部材料 | 调用方传入 `context` |
| **发言池** | 讨论中所有人说过的话，实时累积 | 圆桌维护 |

**库里没有角色概念。** 没有「主持人」「审核者」「提案人」这些内置身份。谁是主持人，只存在于项目那个席位文件的正文里。

## 它不是什么

| 不是 | 理由 |
| --- | --- |
| 不是角色库 | 预设角色违反「Prompts are business assets: they live in each project」 |
| 不是流程编排器 | 不内置阶段、批次、角色分工；这些是项目在席位文件里的表达 |
| 不是模型适配层 | 文本调用统一走 `@ci-kit/ai` |
| 不是采集器 | 素材由调用方传入，圆桌不抓 RSS、不读网页、不扫数据库 |
| 不是决策器 | 结论由程序按席位投票算出，模型只提供判断材料 |
| 不是流式大会 | CLI/CI 场景下流式对日志和管道无价值 |

## 与项目的能力边界

这是本设计最重要的一条分工：

| 谁 | 负责什么 |
| --- | --- |
| **圆桌库** | 提供平台：讨论怎么发生、发言怎么共享、结果怎么算、记录怎么存 |
| **项目（如 wukong-content）** | 定义圆桌：有哪些席位、各自是谁、分几批聊、每批多久、聊什么主题 |

举例说明这条边界：

```
圆桌提供：并发讨论、发言池、可见性、投票判定、记录落盘
          ↓
项目定义：table.md   → 讨论 3 分钟、池上限 5000、阈值 0.6
          seats/*.md → 格罗姆是门店店长，麦迪文做事实核查，萨尔主持
          context    → 今天这篇文章和它的素材
```

圆桌不知道萨尔是主持人。它只知道萨尔在那场讨论里说了话，而萨尔在席位文件里被项目写成了「负责引导与收口的人」。

## 为什么单独成包

monorepo 的设计规则是：

> - Modules do not depend on each other except through `@ci-kit/http`.
> - Prompts are business assets: they live in each project, not in this package.

放进 `@ci-kit/ai` 会让它从「一次调用」膨胀成「一个框架」，且改讨论规则会逼所有用 `text()` 的人跟着升版本。

依赖方向：

```
roundtable ──> ai（调用 text()）
           └─> http（不直接用，保持设计规则一致）
```

## 议题不是参数

> **圆桌开一场会，不需要人给方向。**

议题是**某个席位在讨论中先说出来的内容**，与其他发言地位相同。谁的席位文件被写成「负责提出议题」，谁就负责开场。

这让人工指定议题成为**可选覆盖**（`--topic`），用于人工校准或复盘，不是常态输入。

## 能力验证

`wukong-content`（悟空搭档公众号流水线）作为能力验证样例：如果圆桌的表达能覆盖它的需求，说明抽象够用。

| wukong-content 的需求 | 圆桌中的表达 |
| --- | --- |
| 四个角度同时审一篇文章 | 四个席位同时在场，`durationMs: 180000` |
| 审核者要知道文章，但不必看见他人意见 | `sees: none` |
| 主持人最后总结并给出结论 | 主持人席位在提示词里被写成「负责收口」，它会在讨论后段说出来 |
| 最多重来 3 轮 | `maxAttempts: 3` |
| 发言池不超过 5000 token | `maxPoolTokens: 5000` |
| 有人提出合规否决就不能发表 | `canVeto: true` + 程序裁决 |

## 与上一版设计的关系

上一版把圆桌设计成「阶段 × 执行模式（serial / parallel）」，并把 `propose` / `converge` 当作有特殊含义的阶段，席位还被强制分配到自己参加的阶段。

那套模型不像真实圆桌：真人开会不是「先开提案阶段，等它结束再开讨论阶段」。真人是同时在场、随时接话，由时间划定这场会聊多久。

现在改为：**一场讨论，所有人同时在场，按时间截止，发言实时共享。** 流程仍然是「讨论 → 结论」，但讨论内部不再有任何机械切分。
