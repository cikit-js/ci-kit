# 圆桌配置（table）

`.ci-kit/roundtable/table.md` 只描述**这场会怎么开**：聊多久、花多少、怎么裁决。

它不定义议题，也不写任何具体业务——开一场会时还没确定要聊什么，主题由调用方在运行时传入。

## frontmatter

```markdown
---
title: 文章审核圆桌
durationMs: 180000
maxPoolTokens: 3000
reasoningEffort: low

threshold: 0.6
onVeto: abort
maxAttempts: 1
---
```

## 字段

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 目录名 | 会议名称，写入 `record.md` 标题 |
| `durationMs` | number | `180000` | 这场讨论开多久（3 分钟） |
| `maxPoolTokens` | number | `3000` | 发言池上限，超出时丢弃最早发言 |
| `reasoningEffort` | enum | 不传 | 思考强度：`none` / `low` / `medium` / `high` / `max`。不传时用厂商默认 |
| `threshold` | number | `0.5` | 加权通过率门槛，0–1 |
| `onVeto` | enum | `re-propose` | 被否决后的动作：`re-propose` / `revise` / `abort` |
| `maxAttempts` | number | `3` | 最多循环几轮 |

**没有任何调用次数预算。** 成本由三件事共同控制：整场时长、发言池上限、单次发言长度（`seat.maxTokens`）。前两个是时间与上下文，第三个是输出，合起来就是全部开销。

## 一场会只有一场讨论

所有参与席位**同时开聊**，到时间全部停下，然后程序裁决。

```
读配置 → 拿到参与者、时长、预算
  ↓
所有人同时开始循环
  每次请求带：主题 + 简介 + 材料 + 发言池快照
  说一句 → 入池 → 再说
  ↓
到 durationMs（默认 3 分钟），停止发起新请求
  ↓
程序按投票裁决
```

没有批次划分，没有「先讨论再审核」，也没有特殊阶段。

### 谁负责什么，写在席位上

项目想让某个角色最后总结、或者先独立判断，靠的是**席位配置**，不是流程切分：

| 想达到的效果 | 做法 |
| --- | --- |
| 某席位最后归纳大家意见 | 在它的席位正文里写「你负责在讨论中归纳」，模型会据此行动 |
| 某席位做独立判断 | 在它的席位正文里写「先自己判断，不要跟着别人」 |
| 某席位有否决权 | `canVeto: true` |
| 某席位说得比别人少 | 调低它的 `seat.maxTokens` |

圆桌不知道谁是主持人，只知道谁在那场讨论里说了话。角色语义全在席位文件的正文里。

## 主题由调用方传入

`table.md` 里没有主题字段——写配置的时候还不知道今天要聊什么。

| 输入 | 来源 | 说明 |
| --- | --- | --- |
| `topic` | `runRoundtable({ topic })` | **必填**。这场讨论要回答的问题 |
| `brief` | `runRoundtable({ brief })` | 可选背景说明 |
| `context` | `runRoundtable({ context })` | 可选外部材料，逐条编号分发 |

三者与发言池在提示词里分区标注，模型能分清「要讨论什么」和「大家说了什么」。

`topic` 缺失时直接报错：没有主题的讨论没有意义。

## 成本控制

没有调用次数预算。三项控制共同决定一场会的开销：

| 控制项 | 管什么 | 触顶后的行为 |
| --- | --- | --- |
| `durationMs` | 整场会开多久 | 不再发起新请求，讨论结束 |
| `maxPoolTokens` | 每次请求的输入长度 | 丢弃池内最早的发言，滚动前进 |
| `seat.maxTokens` | 单次调用的正文预算（默认 600） | 模型输出被截断 |

### 发言池上限

`maxPoolTokens` 默认 3000，约 40 条发言。超出后不是停止讨论，而是**丢掉最早的发言**：

- 输入 token 恒定，成本可预测
- 3 分钟讨论通常产生 20–40 条，正常到不了上限
- 只有在模型返回极快、说了很多时才会触发

代价是长讨论会「忘了开头」。所以它设得比典型讨论略大，平时不触发，只防跑飞。

## 裁决

**模型永远不返回 `approved`。** 席位投出 `verdict` / `score` / `issues`，通过与否由程序算。

```
本场结论 =
  若任一 canVeto 席位给出 veto          → 否决
  否则若 加权通过票 / 加权总票 ≥ threshold → 通过
  否则                                 → 否决
```

理由：模型说「通过」不可靠，且会与文字建议矛盾。程序裁决保证同一份记录永远得出同一结论。

席位在讨论中可以自由发言，但**投票只取它投出的判断**：`seat.output: json` 的席位返回结构化 `verdict` 时计入。同一席位多次发言投出多个 `verdict` 时，以最后一次为准。

### 一票否决

`canVeto: true` 是强权力，任一否决即否决。多人表决用 `weight` 表达，两者不混用：

| 需求 | 用哪个 |
| --- | --- |
| 某席位说了不就不能过 | `canVeto` |
| 多数人同意就能过 | `weight` + `threshold` |
| 少数人反对要压过多数 | 改用 `canVeto` |

否决必须带理由。空理由的否决记 `invalid-veto`，不计入。

### onVeto 的三种动作

| 值 | 行为 | 适用 |
| --- | --- | --- |
| `re-propose` | 重新开一场讨论，把否决理由作为输入 | 方向本身不对 |
| `revise` | 重开讨论，把否决理由作为输入并保留上一场发言 | 方向对、做法不对 |
| `abort` | 立即结束，保留全部记录 | 不可接受即停 |

## 校验

| 规则 | 行为 |
| --- | --- |
| `durationMs` 非正整数 | 报错 |
| `maxPoolTokens` 非正整数 | 报错 |
| `threshold` 不在 0–1 | 报错 |
| `maxAttempts` 非正整数 | 报错 |
| 没有启用任何席位 | 报错 |
| 运行时缺 `topic` | 报错 |

## 最终配置

一份可直接用的 `table.md`（正文部分见下）：

```markdown
---
title: 文章审核圆桌
durationMs: 180000
maxPoolTokens: 5000
reasoningEffort: low

threshold: 0.6
onVeto: abort
maxAttempts: 1
---

# 文章审核圆桌

一篇文章写完、通过机器审核之后，交给这张圆桌再过一遍。

四个席位同时读，互相能听见对方：

- 麦迪文核查事实有没有依据
- 格罗姆代表门店店长，判断看完能不能用
- 乌瑟尔判断能不能公开，对硬性退稿事项有单独否决权
- 吉安娜负责标题、开头、结构和表达

萨尔负责收口：归纳共识、标出分歧、排出作者应当先处理的那一条。

裁决由程序完成，不由任何席位宣布。
```

正文是**给人看的说明书**，不参与运行。它回答「这张桌子为什么这么摆」，席位分工写在这里便于协作者理解。

## 配套的席位配置

圆桌配置只管「这场会怎么开」。谁在场、各自是什么人、有多大的权，写在 `seats/*.md`：

```yaml
---
id: uther
role: 合规与风险

identity:
  name: 乌瑟尔
  title: 内容合规审核
  background: 见过因为一句话被投诉、被截图传播的案例

persona:
  stance: 拿不准的一律删
  style: 冷静、不带情绪

seat:
  canVeto: true
  weight: 1
  maxTokens: 80
  fallback: skip
  output: json
---

你负责判断这篇文章能不能公开。
一次只说一句：哪里不能发，或者可以发。
```

**没有任何 `phase` 字段**——席位不登记自己参加哪场讨论，所有 `enabled: true` 的席位都在那一场里。
