# 圆桌（roundtable）

给一组 AI 一张桌子，让它们像人一样**你一句我一句地聊**，聊完给出结论。

## 一句话定位

> **圆桌只提供平台：讨论怎么发生、发言怎么共享、结果怎么算。**
> **角色是谁、聊什么、聊多久，全由项目定义。**

库里没有一个角色名。主持人、审核者、读者视角都是项目在席位文件里写的，圆桌只负责让他们能坐在一起说话。

## 一场会是什么样

```
调用方给出主题：「这篇《…》能不能发」
  ↓
所有人同时开聊，3 分钟
  guard / reader / editor / host 各自循环发言
  每次调用都带上「到目前为止所有人说过的话」
  3 分钟到，全部停下
  ↓
程序依据席位投出的判断，算出结论
```

**没有轮次，没有串并行模式，没有批次划分。** 一场会就是一段讨论，由时间划定长度。

## 已确认决策

| # | 问题 | 结论 |
| --- | --- | --- |
| 1 | 包位置 | 独立包 `@ci-kit/roundtable`，不并入 `@ci-kit/ai` |
| 2 | 讨论形式 | 只有一种：并发讨论，按时间截止。不提供串行/并行模式 |
| 3 | 角色语义 | 库不内置任何角色。主持人、审核者都是项目定义 |
| 4 | 发言可见性 | 没有可见性参数。所有席位共享同一份发言池，含自己说过的话 |
| 5 | 裁决 | 程序按 `canVeto` / `weight` / `threshold` 计算，模型只提供判断材料 |
| 6 | 成本控制 | 不设调用次数预算。三项封顶：`durationMs`（时长）、`maxPoolTokens`（输入）、`seat.maxTokens`（单次输出） |
| 7 | 主题从哪来 | 运行时参数 `topic` 必填。`table.md` 不写主题——配的时候还不知道今天聊什么 |
| 8 | 发版 | 跟随 monorepo 统一发版 |
| 9 | 席位 md 分组 | `id` / `role` / `enabled` 顶层，`identity` / `persona` / `seat` 分组 |

## 与上一版设计的差异

此前把圆桌设计成「阶段 × 执行模式」：每个阶段可以串行或并行，席位被强制分配到具体阶段，还有 `propose` / `review` / `converge` 的语义区分。

那套模型的问题在于**它不像真实的圆桌**。真实开会不是「先开提案阶段，等提案阶段结束，再开讨论阶段」。真人是同时在场、随时接话，由时间划定这场会聊多久。

现在改成：**一场讨论，所有人同时在场，按时间截止，发言实时共享。** 流程仍然是「讨论 → 结论」，但讨论内部没有任何人工切分的边界。
